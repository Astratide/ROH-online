# Skill: 创建泰拉怪物 HTML 数据卡

本 Skill 用于在 Rhodes-Operation-Handbook 项目中创建或整理怪物数据卡 HTML 文件。

项目中的怪物数据卡主要分为两种：

1. 小怪页面：
   - 一个 HTML 文件内通常包含两个怪物数据块。
   - 第一个是较弱版本。
   - 第二个是更强版本。
   - 两个版本通常共用主题、机制、描述风格，但强版本拥有更高 CR、HP、伤害、技能或额外动作。

2. Boss 页面：
   - 一个 HTML 文件通常只包含一个 Boss 数据块。
   - Boss 页面可包含领袖图标、特殊描述、引言、传奇动作、神话特性、神话动作等。
   - Boss 通常使用更复杂的特质、动作、反应、传奇动作结构。

创建前必须优先参考项目中已有文件，例如：
- `深池逐火战士.html`
- `弧光锋卫.html`
- `爱布拉娜.html`
- `画中人/阿咬.html`、`画中人/妒.html`（两行式简介、家系特性、桌游化简化的最新范例）

不要创造全新的 HTML 风格，除非用户明确要求。

---

## 一、通用 HTML 文件结构

新建怪物 HTML 文件时，优先使用以下项目风格：

```html
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN">

<html xmlns:o="urn:schemas-microsoft-com:office:office">
<head>
<meta content="text/html; charset=UTF-8 http-equiv="Content-Type"/>
<meta content="IE=11" http-equiv="X-UA-Compatible">
<title>[页面标题]</title>
<link href="../../style.css" rel="stylesheet"/>
<link href="../../stat-block.css" rel="stylesheet"/>
<meta content="IE=11" http-equiv="X-UA-Compatible"/>
</meta>

</head>
<body>
[页面内容]
<br></body>
</html>
```

注意：

1. 如果 HTML 文件位于 `第七章：生物图鉴/某阵营/` 下，CSS 路径通常是：
   ```html
   <link href="../../style.css" rel="stylesheet"/>
   <link href="../../stat-block.css" rel="stylesheet"/>
   ```

2. 如果 HTML 文件位于 `第七章：生物图鉴/` 直属目录下，CSS 路径通常是：
   ```html
   <link rel="stylesheet" href="../style.css">
   <link rel="stylesheet" href="../stat-block.css">
   ```

3. 不要随意更改项目现有的 HTML 4.01 Transitional 风格。
4. 文件实际以 **UTF-8 无 BOM** 保存；`<meta>` 行沿用相邻怪物卡的原样写法，不要另行改写。保存后应确认中文不会乱码。
5. CHM 项目中应避免复杂脚本、动态路径或不稳定链接。
6. 图片路径必须使用项目内真实存在的相对路径。
7. 如果图片不确定，使用 `[待匹配图片]`，不要编造路径。
8. 怪物卡页面直接把内容平铺在 `<body>` 中，不要再套一层 `<div id="content">`；项目现有的怪物卡都是这种写法。

## 二、小怪页面结构

小怪页面通常包含两个级别：

1. 普通 / 弱版本
2. 精锐 / 强版本

两个怪物数据块放在同一个 HTML 文件中，中间使用：

```html
<br><br>
```

分隔。

小怪页面整体结构如下：

```html
<body>
[弱版本展示区]
<br>
[弱版本数据卡]

<br><br>

[强版本展示区]
<br>
[强版本数据卡]


</body>
</html>
```

## 三、小怪展示区模板

每个小怪版本在数据卡前，需要有一个展示区。

模板如下：

```html
<h1 class="title">[中文名] [English Name]</h1>
<span class="grey">[攻击距离/伤害类型]；[敌人级别] [种族或标签]</span>

[可选：精英图标]

<table style="height: 10em;">
<tr><td>
<IMG style="width: 10em; height: 10em; vertical-align: top;" src="[头像图片路径]" >
</td>
<td>
<b>[小标题一]。</b>[身份、外观、能力概述]<br>
<b>[小标题二]。</b>[性格、特色或彼此的相处方式]<br>
</td></tr>
</table>
<br>
```

### 简介：固定两行制

简介必须写成**两行**，每行都以「**4–8 字加粗小标题 + 句号**」开头，然后接一句说明：

- **第一行**：这只怪物是什么——身份、外观、由谁创造、在族群中的位置。
- **第二行**：它的性格、行为特色或弱点，让 DM 一眼知道该怎么演它。
- 正文可以适度改写自原作描述，但保留官方原文的关键措辞，不要扩写设定、语录或背景故事。
- **不要把规则效果写进简介。** 数值与能力属于数据卡；简介只负责气氛与扮演提示。

示例：

```html
<td>
<b>平凡的墨魉。</b>画家随手命名的化物，成群结队地在夕的画中游荡。<br>
<b>爱玩成性。</b>聪明到听得懂人话，却把一切都当成游戏，落单时会显得格外孤单。<br>
</td>
```

```html
<td>
<b>强壮的墨魉。</b>画家笔下最魁梧的一只，身材高大、体格强壮，却不太擅长思考。<br>
<b>要靠朋友。</b>总是一头栽进最简单的陷阱，最后得靠阿咬们把它拖出来。<br>
</td>
```

### Boss 的简介可以更长

小怪两行足够；**Boss 写 3–5 段**，每段仍然以「4–8 字加粗小标题 + 句号」开头。Boss 的简介是这个角色的门面，除了气氛，还要承担三件事：

1. **来历**——它从哪来、是谁造的、为什么叫这个名字。
2. **外形与特征**——颜色、轮廓、体量、在什么天时出现。
3. **含蓄地暗示机制与破法**——不写数值，只写画面。例如「五兵难伤」暗示高 AC 与抗性，「那些墨会替它再挡一次」暗示临时生命值，「它便多出一颗头颅」暗示第二形态，「砍倒它未必算完」暗示不会真正死亡。

示例（自在 "Free"，BOSS）：

```html
<td>
<b>夕绘出的怪物。</b>灰齐山景她画了千百次，终于画腻，索性让笔行自己的道。墨自卷上蜷起，缠烟披墨，盘岩昂首——回头看她的，只是一只幼兽。笔非笔，墨非墨，卷非卷，形物皆伪，可那点灵动让她动了兴致，于是它有了名字。<br>
<b>色青似重峦。</b>有兽色青，形似重峦，其数十一，戴月披烟。须靛如林，骨峭如石；云涛微茫、暮色沉下来的时候，它才显出轮廓。<br>
<b>五兵难伤，五火难防。</b>凡俗的刀兵砍不进它的骨，火焰也未必烧得穿；而若真烧到血肉，涌出来的只有墨泉——那些墨会替它再挡一次，逼得人从头再来。<br>
<b>雾尽则两首无羁。</b>雾穷烟尽，束缚松开，它便多出一颗头颅、多出一轮攻势。别急着以为砍倒它就算完：其形亦伪，其物亦伪，晨昏方易，它还会在晨光里再立起一次——直到一夕烬尽。<br>
</td>
```

写 Boss 简介时优先到原作的角色档案、模组文本、活动歌谣里取材；那些句子里往往已经埋好了外形、天时与结局，直接引用比自己编更有分量。

### 字段说明

- `[中文名]`：例如 `深池逐火战士`、`阿咬`。**不要加中文引号**（见第十六节）。
- `[English Name]`：例如 `Dublinn Flamechaser Soldier`、`"Bitey"`。官方名自带直引号的，保留原样。
- `[攻击距离/伤害类型]`：例如：
  - `近战 物理`
  - `近战 法术`
  - `近战 远程 物理 法术`
- `[敌人级别]`：例如：
  - `普通`
  - `精英`
  - `领袖`
- `[种族或标签]`：写 PRTS 的种类名，例如：
  - `任意`
  - `黎博利`
  - `类人（龙类；德拉克）`
  - `化物`
- `[头像图片路径]`：必须来自项目图片资源目录。

### 精英图标

如果该小怪属于精英敌人，可在 `</span>` 之后、头像表格之前加入：

```html
<div style="position: relative;">
<IMG style="left: 400px; top: -4em; position: absolute;" src="../../图片资源/图标_精英敌人.png" >
</div>
```

普通敌人通常不需要图标。

## 四、小怪数据卡模板

小怪数据卡使用：

```html
<div class="monster_container">
<h1 class="line">[中文名]丨[Short English Name]</h1>

<div class="sub-line">[体型][生物类型]（[大类]；[家系]），[阵营]</div>
<table class="stat">
<tr><td><b>AC</b> [AC]</td>
<td width="40%"><b>先攻</b> [先攻调整]（[先攻值]）</td></tr>
<tr><td colspan="2"><b>HP</b> [HP]（[生命骰]）</td></tr>
<tr><td colspan="2"><b>速度</b> [速度]</td></tr>
</table>

[六属性表]

<table class="stat">
[技能/抗性/免疫/装备/感官/语言/CR 等]
</table>

<h2 class="line">特质 Traits</h2>

[特质列表]

<h2 class="line">动作 Actions</h2>

[动作列表]

[可选：附赠动作]

[可选：反应]
</div>
```

### 生物类型行必须带家系

类型行格式为：

```text
[体型][生物类型]（[大类]；[家系]），[阵营]
```

- `[大类]` 用 PRTS 的种类名，例如 `化物`、`坍缩体`、`萨卡兹`。
- `[家系]` 是该怪物所属的具体族群，例如 `墨魉`、`源石虫`、`猎狗`。
- 两者之间用**全角分号 `；`** 分隔，整体放在全角括号内。
- 没有明确家系时可以只写大类，例如 `中型亡灵（任意），守序中立`。

示例：

```html
<div class="sub-line">中型异怪（化物；墨魉），无阵营</div>
<div class="sub-line">大型异怪（化物；墨魉），无阵营</div>
<div class="sub-line">中型类人（萨卡兹），守序中立</div>
```

家系名很重要：同一家系的怪物会共用一条以家系名开头的特性（见第八节）。

### 属性调整规则

属性调整值应按 D&D 5e 规则计算：

```text
属性调整 = floor((属性值 - 10) / 2)
```

例如：

- 8-9：-1
- 10-11：+0
- 12-13：+1
- 14-15：+2
- 16-17：+3
- 18-19：+4
- 20-21：+5

豁免列默认等于属性调整。

如果该怪物具有某项豁免熟练，则：

```text
豁免 = 属性调整 + PB
```

不要把所有豁免都加熟练。普通小怪通常只有 0-2 项豁免熟练，强怪可略多，但仍应保守。

## 六、基础信息表字段顺序

项目中的基础信息表通常采用如下顺序：

```html
<table class="stat">
<tr><td><b>技能</b> [技能列表]</td></tr>
<tr><td><b>抗性</b> [伤害抗性]</td></tr>
<tr><td><b>免疫</b> [伤害免疫或状态免疫]</td></tr>
<tr><td><b>装备</b> [装备]</td></tr>
<tr><td><b>感官</b> [感官，被动察觉]</td></tr>
<tr><td><b>语言</b> [语言]</td></tr>
<tr><td><b>CR</b> [CR]（XP [XP]；PB +[PB]）</td></tr>
</table>
```

不是每个字段都必须出现。

可省略字段包括：

- 技能
- 抗性
- 免疫
- 装备

但以下字段通常应保留：

- 感官
- 语言
- CR

如果字段未知，使用占位符：

```text
[待补充]
[待确认]
[CR 待确认]
```

### 先攻的算法

先攻**不等于**敏捷调整值。5.5e 的数据卡把先攻单独印成 `先攻 +X（Y）`，并允许它明显高于敏捷调整值 —— 目的就是**不让高位格的生物被玩家抢先手打一轮空血**。写作时照填数值即可，**不需要在特质里解释原因**。

三档：

| 档位 | 算法 | 适用 |
|---|---|---|
| 基础 | 敏捷调整值 | 普通小怪、行动迟缓的巨物 |
| 迅捷 | 敏捷调整值 + PB | 概念上灵敏的生物、普通首领 |
| 顶端 | 敏捷调整值 + 2×PB | 巨兽、岁兽碎片、黑冠一类的存在 |

项目内实例（均已核对）： 

| 卡 | CR | PB | 敏捷 | 先攻 |
|---|---|---|---|---|
| 夕 | 24 | +7 | +3 | **+17** = 3 + 2×7 |
| 令 | 25 | +8 | +4 | **+20** = 4 + 2×8 |
| 特雷西斯，黑冠尊主 | 26 | +8 | +4 | **+20** = 4 + 2×8 |
| 假想敌：胄 | 30 | +9 | +0 | **+18** = 0 + 2×9 |
| 自在 | 20 | +6 | +1 | +7 = 1 + 6（单 PB） |
| 起源复仇者 | 13 | +5 | +3 | +3（不加） |

同一个设计语言也体现在豁免上。**官方数据里有两个硬锚点**（取自 2024 版基础规则的西语镜像，2026-11 检索）：

| 生物 | CR | PB | 敏捷 | 敏捷豁免 | 先攻 |
|---|---|---|---|---|---|
| 远古红龙 Ancient Red Dragon | 24 | +7 | 10（+0） | +7 | **+14 = 2×7** |
| 泰拉斯奎 Tarrasque | 30 | +9 | 11（+0） | +9 | **+18 = 2×9** |

来源：[Dragón rojo anciano](https://nivel20.com/games/dnd-2024/creatures/210124-dragon-rojo-anciano)、[Tarasca](https://nivel20.com/games/dnd-2024/creatures/210248-tarasca)。

两者敏捷都只有 +0，敏捷豁免却都等于 PB，先攻都等于**两倍 PB**。这就是「低敏捷、高豁免、高先攻」三位一体：位格越高，越不该被某一项属性拖住。因此本项目给巨兽／岁兽／黑冠写 `敏捷调整值 + 2×PB` 是有官方依据的，**不需要在特质里解释原因**。

括号里的数值换算：`Y = 10 + X`，X 带符号、Y 不带（例：`+20（30）`、`-2（8）`）。

## 七、小怪弱版本与强版本设计规则

### 弱版本

弱版本通常具有：

- 较低 CR。
- 较少动作选项。
- 通常没有附赠动作或反应。
- 通常没有复杂控制。
- DPR 和 HP 应接近目标 CR 推荐值。
- 特质数量一般 1-2 个。
- 动作一般包括 1 个普通攻击，可能没有多重攻击。

示例结构：

```html
<h2 class="line">特质 Traits</h2>

<b>[特质名称 English Name]。</b>[规则描述]<br>

<h2 class="line">动作 Actions</h2>

<b>[武器或能力名称 English Name]。</b><i>近战攻击检定：</i>+[AB]，触及[距离]尺。<i>命中：</i>[平均伤害]（[伤害骰]）[伤害类型]。<br>
```

### 强版本

强版本通常在弱版本基础上增强：

- CR 提高。
- HP 增加。
- 可能拥有更高属性或技能。
- 通常获得多重攻击。
- 攻击伤害提高。
- 可能获得附赠动作、反应或额外控制。
- 可继承弱版本的核心特质，但应调整描述名称一致性。

示例结构：

```html
<h2 class="line">动作 Actions</h2>

<b>多重攻击 Multiattack。</b>[怪物名]发动两次[攻击名称]攻击。<br>
<b>[攻击名称 English Name]。</b><i>近战攻击检定：</i>+[AB]，触及[距离]尺。<i>命中：</i>[平均伤害]（[伤害骰]）[伤害类型]，[附加效果]。<br>

<h2 class="line">附赠动作 Bonus Actions</h2>

<b>[附赠动作名称 English Name]。</b>[规则描述]<br>
```

强版本不要只是单纯堆高数值。优先通过一个清晰机制表现其“更强”。

## 八、桌游化简化约定

本项目的数据卡以**桌上跑团的实际操作量**为第一优先。规则能省一次掷骰、少追踪一个状态，就应该省。以下约定自「画中人」系列起成为标准，新建或改稿时都适用。

### 1. 家系通用特性用家系名开头

同一家系的怪物共用一条特性，主语写**家系名**，不写「怪物」，也不写具体个体名：

```html
<b>明晦相克 Light and Gloom。</b>墨魉对先攻值为奇数的生物发动的攻击具有<b class="green">优势</b>，对先攻值为偶数的生物发动的攻击具有<b class="green">劣势</b>。<br>
```

- 这条特性在该家系每个个体的数据卡里都要重复出现，位置放在 Traits 第一条。
- **不要在正文里写“见某某页”或“另有地图机制页”。** 项目当前的分工是：家系共有的机制直接落在每张数据卡上，不额外建规则页、不依赖场上标记物。
- 若原机制需要地图、印记、属性标记等大量场上状态，先尝试把它收缩成一条只依赖既有数值（先攻、生命值、豁免结果）的特性。

### 2. 「特质」只放被动，「动作／附赠动作」放主动

- 常驻、被动、无需消耗动作的效果 → `特质 Traits`。
- 需要消耗动作或附赠动作才能使用的效果 → 对应的动作区。
- 辅助、支援、治疗、位移类能力优先做成**附赠动作**，并用 `（1/日）` 限次。

```html
<h2 class="line">附赠动作 Bonus Actions</h2>
<b>同群相救 Pack Rescue（1/日）。</b>认真的阿咬为一个5尺内盟友恢复5点生命值，若为<b class="green">浴血</b>期间则提升至10点。<br>
```

不要把“可以主动使用的能力”塞进特质——那样 DM 每次都要回查它到底要不要花动作。

### 3. 少用「反应」，能改成动作就改

反应要求全场额外追踪触发条件。除非触发点非常明确且值得保留（例如「被攻击命中时」），否则优先改写成主动动作：

```html
<b>同调自爆 Resonant Detonation。</b>得意触碰一个先攻比自己高的生物，然后死亡并触发其死亡爆炸。<br>
```

### 4. 限次能力用（1/日），不用（充能5~6）

- 默认写 `（1/日）`。
- 只有确实需要在同一场战斗中反复使用、且节奏上依赖它的能力，才写 `（充能5~6）`。
- 采用 `（1/日）` 时，不要再写「蓄力累积」「下回合结算」「被打断则浪费」这类流程。

### 5. 条件式附加效果用「成功或失败：」

无论豁免成败都会发生的附加效果，单独用 `成功或失败：` 引出，不要塞进失败行：

```html
<i>失败：</i>55（10d10）暗蚀伤害。<i>成功：</i>仅受半伤。<i>成功或失败：</i>源自该生物15×15尺范围内的地面被墨色印记覆盖，位于印记上的生物遭受的攻击具有<b class="green">优势</b>，印记持续1分钟。<br>
```

### 6. 区域与地形写得极简

- 区域形状术语标绿加粗：`<b class="green">球状</b>`、`<b class="green">锥状</b>`、`<b class="green">立方</b>`、`<b class="green">柱状</b>`、`<b class="green">光环</b>`。
- 方形区域直接写尺寸，例如 `15×15尺`。
- 地形、印记、云雾、法阵类效果**只给一个后果**，不要多层叠加。常用模板：

```html
位于印记上的生物遭受的攻击具有<b class="green">优势</b>，印记持续1分钟。
```

- 「施加一个状态」类效果同样只给一个后果，常用模板：

```html
该生物遭受的攻击具有<b class="green">优势</b>，持续直到其下次受到治疗为止。
```

### 7. 特质控制在 2–3 条

- 一个数据卡的特质通常 2–3 条，强怪或 Boss 可放宽。
- **纯画风、纯性格的特性不要写进数据卡**，例如「孤僻」「好伙伴」「愚钝」这类只影响扮演的条目——把它们并入简介即可。
- 弱点类特性（例如「不视高飞」）可以保留，也可以删掉；删掉时把原因写进简介。判断标准是：这条弱点是否会让这场遭遇的战术明显变化。

### 8. 免疫力竭即代表无需呼吸、进食、睡眠

不要写：

```text
它不需要呼吸、进食或睡眠。
```

5.5e 已把这条并入「免疫<b class="green">力竭</b>」，重复书写只会让卡变长。

### 9. 常用机制模板（照抄即可）

这些模板已经在「画中人」系列验证过，遇到同类概念直接套用，不要重新发明措辞。

**器伥／显出本体**（「将进酒」系列）。家系与材质合并成一条，材质三选一（木散 Splinter／瓷脆 Porcelain／金坚 Iron）：

```html
<b>器伥·[材质] Waregeist·[Material]（[N]/日）。</b>当[怪物]因伤害使生命值降至0时，其可以改为将生命值降至1，并化作微型大小的[本体]。[怪物]生命值为1期间还会获得<b class="green">隐形</b>和<b class="green">失能</b>状态，且其移动不引发借机攻击。[材质句]且当在其他生物体内结束回合时，对其造成5（1d10）点力场伤害。<br>
```

材质句：

- **木散 Splinter**（限次 2/日，不另加句子——「挡两次」本身就表达了分裂成两份）
- **瓷脆 Porcelain**：`期间[怪物]还免疫钝击、穿刺与挥砍伤害。`
- **金坚 Iron**：`[怪物]生命值为1期间，其AC获得+4加值。`

三点必须写全，缺一不可：

1. **化作微型大小的[本体]**——体积与样貌的变化，要让 DM 一眼能想象出桌上摆的是什么。
2. **力场伤害**——战棋里没有「保护点」，1 血失能的散件玩家会直接无视；必须让它能钻进生物体内、在其回合结束时咬人。
3. **简介里写「死亡后化作[本体]」**——让 DM 不用翻规则就知道它死后会变成什么。

**易伤标记**（原作的「属性变化／印记反转」一律收缩成这一条）：

```html
该生物遭受的攻击具有<b class="green">优势</b>，持续直到其下次受到治疗为止。
```

**地形／印记**（原作的「创造明晦地形」）：

```html
位于印记上的生物遭受的攻击具有<b class="green">优势</b>，印记持续1分钟。
```

**引敌／嘲讽**（原作「嘲讽等级+1」，只有这样才能真正作用到 PC）：

```html
<b>引敌 Draw Fire。</b>位于[怪物]10尺内的生物进行攻击时，若不将[怪物]作为目标，则该次攻击检定具有<b class="green">劣势</b>。<br>
```

**见缝插针／背刺**（把「优先攻击异属性」这类判断转成伤害）：

```html
<b>见缝插针 Backstab。</b>每回合一次，当[怪物]的攻击检定具有<b class="green">优势</b>时，该次攻击命中额外造成7（2d6）穿刺伤害。<br>
```

**无可阻挡**（原作「只能被同属性阻挡」，5e 中改为不吃减速与控制）：

```html
<b>无可阻挡 Unstoppable。</b>[怪物]的速度不会被困难地形降低。使其陷入<b class="green">受擒</b>或<b class="green">束缚</b>状态的效应在其回合结束时结束。<br>
```

**破桎／蓄力屏障**（限次，改写掉逐秒蓄力的流程）：

```html
<b>破桎之躯 Barrier of Regret（1/日）。</b>[怪物]在其回合开始时获得60点<b class="green">临时生命值</b>并开始蓄力。若在其下个回合开始时这些临时生命值仍未被击破，[怪物]立即爆发：15尺内每个生物进行一次敏捷豁免。<i>失败：</i>84（12d12）暗蚀伤害。<i>成功：</i>仅受半伤。<br>
```

**二阶段／再生**（BOSS 专用，替代「血量清空再复活」的多重血条）：

```html
<b>再生之夕 Rebirth of Dusk（1/次战斗）。</b>[BOSS]首次将生命值降至0时不会死亡。在其下个回合开始时，它恢复全部生命值并进入第二形态：攻击检定获得+2加值，<b>多重攻击</b>改为三次[攻击名称]，且<b>[另一限次特性]</b>视为尚未使用。<br>
```

## 十一、Boss 常见模块

### 1. 特质 Traits

```html
<h2 class="line">特质 Traits</h2>

<b>[特质名称 English Name]。</b>[规则描述]<br>
```

Boss 特质可以包含：

- 魔法抗性
- 领袖抗性
- 神话特性
- 特殊光环
- 召唤强化
- 形态转换
- 与核心机制相关的特殊规则

#### 神话特性的命名

神话特性是 Boss 的门面之一，命名要比普通特质更隆重。项目内的写法是**多用一段描述性的中文名 + 一个诗意的英文名**，并在括号里标明充能条件：

```html
<b>夕照长明逍遥身 Dusk Everlasting（神话特性；长休或短休充能）。</b>[规则描述]<br>
<b>文明的存续·黑冠尊主 Civilight Eterna（神话特性；长休充能）。</b>[规则描述]<br>
```

取材顺序：

1. 先翻这个角色在游戏里的**档案、铭文、模组文本、活动歌谣**——里面往往直接写着它的弱点、形态变化和结局，拿来当特性名最有力（例如夕的铭文「然其兽难制，晨昏方易，顿尔消弭」直接对应「死了又回来」）。
2. 其次可以从角色的名字本身取典（「自在」出自《庄子》，续命特性可由「方生方死」一类的典故得名）。
3. 英文名不求直译中文全句，取意象即可；用两个词、首字母大写，避免生僻词。

#### 神话特性的标准句式

所有带「第二条血槽」的神话特性都必须照这个句式写，**不要各写各的**：

```text
[怪物]的生命值被降低到0期间，其不会死亡；在本回合结束时，它重设所有生命值以及[领袖抗性使用次数]，然后[其余效应]。
```

三个要素缺一不可：

1. **「期间」而不是「时」**——`生命值被降低到0期间，其不会死亡` 保证它在被击倒的那一回合内有**半个回合的无敌**，玩家无法用「击倒后连击」把它跳过。这是还原明日方舟的**转阶段无敌**。
2. **「在本回合结束时」而不是「立即」**——重置发生在当前回合收尾时，同样是为了留出无敌窗口。
3. **同时重设领袖抗性使用次数**——否则神话形态开打时抗性已经用光，第二形态等于白送。抗性名称按该卡自己的叫法写（领袖抗性／传奇抗性／同协抗性…）。

`重设` 而不是 `恢复` 的理由见下节。

若某张卡的神话特性不含复活（例如只是召唤援军），则不套用此句式。

**例外：自带「离席」效果的可以立即生效。**如果神话特性本身就让怪物**从战场上消失**（离席、传送走、遁入半位面等），那么消失这个动作本身就构成了无敌窗口，不需要再等「在本回合结束时」——直接写「她立即重设所有生命值以及领袖抗性使用次数，并自战场上离席」即可。令（`大梦方醒，此身已远`）就是这种情况。

#### 神话特性里必须写「重设」，不能写「恢复」

神话特性是 Boss 的第二条血槽，它的前提是**任何情况下都必须发生**。但玩家的资源池里有大量反制治疗的手段（魔法武器附带的禁止恢复、某些法术与诅咒），如果这里写「恢复所有生命值」，Boss 的整条第二形态就会被一张反治疗牌废掉。

所以统一写成：

```html
在本回合结束时，她重设所有生命值以及领袖抗性使用次数。
在本回合结束时，它重设所有生命值以及传奇抗性使用次数，然后重新获得全部3层护甲。
```

**「重设」＝直接把当前生命值设定为上限，不是治疗**，因此不受任何禁止恢复、治疗削弱、`生命值无法恢复`一类的效应影响。

同理，凡是「第二条血槽」「必定复活」「阶段转换时回满」这类**不可被阻止**的重置，都用「重设」；而普通的再生、吸血、自愈、临时生命值，仍然正常写「恢复」——那本来就该被反制，是正当的解法。

### 2. 动作 Actions

```html
<h2 class="line">动作 Actions</h2>

<b>多重攻击 Multiattack。</b>[Boss]发动若干次攻击，或将其中一次攻击替换为[其他动作]。<br>
<b>[攻击名称 English Name]。</b><i>近战攻击检定：</i>+[AB]，触及[距离]尺。<i>命中：</i>[平均伤害]（[伤害骰]）[伤害类型]，[附加效果]。<br>
<b>[特殊动作 English Name]（[使用次数]）。</b>[规则描述]<br>
```

多重攻击正文里提到其他攻击项时，**不要加粗**那些攻击项名字：

```html
<b>多重攻击 Multiattack。</b>妒发动两次墨弹攻击。<br>
```

### 3. 施法 Artcasting

项目中通常使用“施法 Artcasting”而不是标准 “Spellcasting”。

格式示例：

```html
<b>施法 Artcasting。</b>[Boss]作为[等级]级施法者施展一道以下法术，使用[属性]作为施法属性（法术豁免 DC [DC]，法术攻击命中+[AB]）。<br>
<i><b>随意：</b><b class="spell">[法术列表]</b></i><br>
<i><b>每项3/日：</b><b class="spell">[法术列表]</b></i><br>
<i><b>每项2/日：</b><b class="spell">[法术列表]</b></i><br>
<i><b>每项1/日：</b><b class="spell">[法术列表]</b></i>
```

### 4. 反应 Reactions

```html
<h2 class="line">反应 Reactions</h2>

<b>[反应名称 English Name]。</b><i>触发：</i>[触发条件]。<i>响应：</i>[效果]。<br>
```

参见第八节第 3 条：能用动作表达的能力不要写成反应。

### 5. 传奇动作 Legendary Actions

```html
<h2 class="line">传奇动作 Legendary Actions</h2>

<p class="grey">传奇动作次数：[次数]。 [Boss]可以在另一生物的回合后立即消耗一次传奇动作来执行以下一道动作。[Boss]在其回合开始时回复所有已消耗的传奇动作次数。</p>
<b>[传奇动作名称 English Name]。</b>[效果]<br>
```

一般规则：

- 普通 Boss：传奇动作次数 3。
- 巢穴或高阶 Boss 可写 `3（巢穴内4）`。
- 传奇动作造成伤害时，估算 CR 时默认使用其中两次可造成伤害的传奇动作计入 DPR。

### 6. 神话动作 Mystic Actions

如果 Boss 拥有神话特性，可加入：

```html
<h2 class="line">神话动作 Mystic Actions</h2>

<p class="grey">如果[Boss]的<b>[神话特性名称]</b>特性被激活，它可以选择以下选项作为传奇动作。</p>
<b>[神话动作名称 English Name]。</b>[效果]<br>
```

注意：

- 神话形态是可选遭遇难度。
- 计算纸面 CR 时通常忽略神话特性和神话动作。
- 若神话形态被激活，实际遭遇难度约提高 25%，XP 通常加倍。

## 十二、项目内常用 HTML class

创建数据卡时应优先使用以下 class：

```text
monster_container
stat
stat-abilities
grey
green
red
spell
syntax
side-box
center
maroon
indent
```

常见用法：

```html
<b class="green">优势</b><b class="green">劣势</b><b class="green">燃烧</b><b class="green">失能</b><b class="green">隐形</b><b class="green">浴血</b><b class="red">深池逐火精锐战士</b><b class="spell">法师护甲</b>```

不要随意新增 CSS class，除非用户明确要求。

`b` 的 `green` / `red` 约定：

- `green`：**规则术语**——优势、劣势、状态名（倒地、束缚、恐慌、力竭、魅惑…）、区域形状（球状、锥状、立方、柱状、光环）、动作类别（撤离、疾走）、战力阈值（浴血）。

### 浴血（Bloodied）的写法

`浴血` 是 5.5e 的战力阈值术语：**生命值为其上限的一半或更低**。它不是一种状态，所以不能写成「浴血状态」。

```html
正确：<b class="green">浴血</b>期间具有<b class="green">优势</b>正确：若他处于<b class="green">浴血</b>，则额外造成9（2d8）火焰伤害
错误：陷入浴血状态 / 获得浴血
```

把「越伤越强」写进攻击项即可，不要单独开一条特质：

```html
<b>燃血长刀 Bloody Longsword。</b><i>近战攻击检定：</i>+9（<b class="green">浴血</b>期间具有<b class="green">优势</b>），触及10尺。<i>命中：</i>23（4d8+5）挥砍伤害；若他处于<b class="green">浴血</b>，则额外造成9（2d8）火焰伤害。<br>
```

如果要让怪物在某个形态下**无视当前生命值、恒定视为浴血**，需要显式写明：「无论其当前生命值多少，他始终视为处于浴血」。

### 燃烧（Burning）的写法

`燃烧` 是**危害（hazard）**，不是状态（condition）。因此不能写「陷入燃烧状态」。

```html
正确：并陷入<b class="green">燃烧</b>正确：并开始<b class="green">燃烧</b>错误：陷入<b class="green">燃烧</b>状态
```

需要限时的话，直接挂时长，不要挂「状态」：

```html
<i>失败：</i>45（10d8）火焰伤害，并陷入<b class="green">燃烧</b>直到其下个回合结束。<i>成功：</i>仅受半伤。
```

判断标准：**5.5e 规则书里列在「状态」表中的才是状态**（倒地、失能、恐慌、束缚、受擒、震慑、麻痹、目盲、耳聋、沉默、中毒、力竭、魅惑、隐形、昏迷…）；燃烧、浴血、以及自定义的流血之类都是危害或阈值，措辞上不要带「状态」二字。
- `red`：**专有名词**——其他生物或重要实体的名称，以及需要突出强调的伤害类型。

## 十三、怪物规则文本风格

规则文本应采用项目现有风格。

攻击格式：

```html
<b>[攻击名称 English Name]。</b><i>近战攻击检定：</i>+[AB]，触及[距离]尺。<i>命中：</i>[平均伤害]（[伤害骰]）[伤害类型]。<br>
```

远程攻击格式：

```html
<b>[攻击名称 English Name]。</b><i>远程攻击检定：</i>+[AB]，射程[距离]尺。<i>命中：</i>[平均伤害]（[伤害骰]）[伤害类型]。<br>
```

豁免格式：

```html
<b>[能力名称 English Name]。</b><i>[属性]豁免检定：</i>DC[DC]，[目标范围]。<i>失败：</i>[失败效果]。<i>成功：</i>[成功效果]。<br>
```

带「无论成败」的附加效应：

```html
<i>失败：</i>[失败效果]。<i>成功：</i>仅受半伤。<i>成功或失败：</i>[无论成败都发生的效果]。<br>
```

触发反应格式：

```html
<b>[反应名称 English Name]。</b><i>触发：</i>[触发条件]。<i>响应：</i>[响应效果]。<br>
```

使用次数格式：

```html
<b>[能力名称 English Name]（1/日）。</b><b>[能力名称 English Name]（充能5~6）。</b>```

**新增能力默认写 `（1/日）`**，理由见第八节第 4 条。

## 十五、图片匹配规则

图片路径必须来自项目内实际存在的图片文件。

优先查找：

```text
../../图片资源/敌人头像/[阵营]/
```

常见命名风格：

```text
头像_敌人_[中文名].png
头像_敌人_[中文名弱版本].png
头像_敌人_[中文名强版本].png
```

**文件名不要带中文引号。** 从 PRTS 下载的 `头像_敌人_“阿咬”.png` 必须改名为 `头像_敌人_阿咬.png`，与项目其余文件保持一致。

敌人图标常见路径：

```text
../../图片资源/图标_精英敌人.png
../../图片资源/图标_领袖敌人.png
```

### NPC / 角色卡的立绘

如果是角色而不是怪物（例如把干员或剧情人物做成 NPC 卡），用 `图片资源/角色图像/[中文名].png`：

- 角色图像多为竖幅半身像，因此图片标签要用 `height` 固定、`width` 自适应，不要套 `10em × 10em` 的方形，否则会拉变形：

```html
<IMG style="height: 10em; width: auto; vertical-align: top;" src="../../图片资源/角色图像/夕.png" >
```

- 怪物卡一律用 `width: 10em; height: 10em;` 的方形头像。

如果有多个候选图片，不要擅自选择，应列出候选让用户确认。

如果没有找到图片，使用：

```html
src="[待匹配图片]"
```

### 从 PRTS 取图

`media.prts.wiki` 可直接用脚本下载，但必须带 `User-Agent` 与 `Referer`；`prts.wiki` 的页面与 `api.php` 从脚本访问常返回 403，此时改用 web 抓取工具读页面。

**原图路径可由文件名直接算出来**（MediaWiki 的哈希目录规则，已验证）：

```text
1. 原图文件名 = 头像_敌人_<PRTS 页面标题，含中文引号>.png
2. 对该文件名做 UTF-8 的 MD5，取十六进制串
3. 原图 URL = https://media.prts.wiki/<md5[0]>/<md5[0..1]>/<URL 编码后的文件名>
```

例如 `头像_敌人_“小躁”.png` 的 MD5 以 `01782f…` 开头，原图即在 `…/0/01/` 下。这样不必先抓渲染页面去反查缩略图地址。

下载后必须**去掉中文引号**再存盘：

```text
头像_敌人_“小躁”.png  →  头像_敌人_小躁.png
```

## 十六、命名与标点

- **怪物名一律不加中文引号。** 官方名带「“”」的（如 `“阿咬”`、`“盛怒”`、`复杂的“妒”`），在项目里统一写成 `阿咬`、`盛怒`、`复杂的妒`。
- 文件名、`<title>`、`<h1 class="title">`、`<h1 class="line">`、正文全部遵守此规则。
- **英文官方名保留原样的直引号**，例如 `阿咬 "Bitey"`、`认真的阿咬丨Serious "Bitey"`。
- 展示区标题与数据卡标题使用同一套名字。

## 十七、创建小怪页面时的工作流程

当用户要求创建小怪页面时，按以下流程：

1. 确认页面标题、阵营文件夹、文件名（不带中文引号）。
2. 确认弱版本和强版本名称，以及它们所属的**家系**。
3. 确认两个版本的 CR。
4. 确认头像图片路径。
5. 查找已有同类文件，优先参考其结构；同家系的最新范例优先。
6. 创建一个 HTML 文件，包含两个数据块。
7. 弱版本先写，强版本后写。
8. 两个版本之间使用 `<br><br>`。
9. 保证两个版本的机制有继承关系。
10. 写两行式简介（第三节）。
11. 类型行写入家系（第四节）。
12. 家系通用特性放在 Traits 第一条。
13. 检查第八节的全部简化约定：动作归属、1/日、成功或失败、术语标绿、特质数量。
14. 完成后总结：
    - 新建文件
    - 弱版本 CR
    - 强版本 CR
    - 使用图片
    - 占位符
    - 需要用户确认的数值

## 十八、创建 Boss 页面时的工作流程

当用户要求创建 Boss 页面时，按以下流程：

1. 确认 Boss 称号、数据卡名称、英文名。
2. 确认目标 CR。
3. 确认是否为神话 Boss。
4. 确认头像、领袖图标、阵营文件夹。
5. 查找已有 Boss 页面，优先参考 `爱布拉娜.html`。
6. 创建一个 HTML 文件，只包含一个 Boss 数据块。
7. 根据需要加入：
   - 领袖图标
   - 引言
   - 领袖抗性
   - 施法
   - 反应
   - 传奇动作
   - 神话特性
   - 神话动作
8. 计算 CR 时默认忽略神话动作。
9. 如果启用神话形态，在 CR 说明中标记实际遭遇难度提高。
10. 完成后总结：
    - 新建文件
    - Boss CR
    - 是否神话形态
    - 使用图片
    - 传奇动作数量
    - 神话动作情况
    - 待确认字段

## 十九、禁止事项

执行本 Skill 时禁止：

1. 不要覆盖已有文件，除非用户明确允许。
2. 不要修改无关文件。
3. 不要编造不存在的图片路径。
4. 不要把不确定内容写成确定事实。
5. 不要大段复制未授权网页内容。
6. 不要创造新的页面结构替代项目现有结构。
7. 不要让低 CR 小怪拥有过多强控制、传奇动作或神话能力。
8. 不要让 Boss 数据只有数值堆叠而没有清晰机制。
9. 不要随意更新索引页，除非用户明确要求。
10. 不要为家系共有的机制另开规则页或依赖场上标记物；写进每张数据卡的特性里。
11. 不要把纯画风特性写进数据卡。
12. 不要在怪物名上使用中文引号。
13. 不要写「不需要呼吸、进食或睡眠」。
14. 不要在多重攻击正文里加粗其他攻击项的名字。
